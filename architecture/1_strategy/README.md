# Strategy & Motivation Layer

_[← EA home](../README.md)_

The top-down context: who has a stake in the repository, why it exists, and
which principles every change is checked against. At Depth 1 this layer is
deliberately light: one document, no capability map and no value stream. Both
would describe the university's enterprise, which is content *inside* the repository, not
this application's own strategy.

## Analysis order

| #   | Document | Elements | Question it answers |
| --- | -------- | -------- | ------------------- |
| 1   | [1_motivation.md](./1_motivation.md) | Stakeholders, Drivers, Assessments, Goals, Outcomes, Principles | Who cares, what pressures them, what must be true? |
| 2   | Capabilities and resources | — | Not written at Depth 1. The capabilities the repository offers are its application services in [4_application](../4_application/1_application-services.md) |
| 3   | Value stream | — | Not written at Depth 1. The flow "export → validate → load → browse → ask" is a scenario in the scope document, not a value stream of an organization |

`1_motivation.md` is where **Principles** live — the constraints that a
proposed change is checked against before anything else. They are few,
load-bearing and testable.
